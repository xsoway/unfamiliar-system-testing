# 测试点维度清单

面向「还不太懂的系统」，用这些**维度**逐项启发「该考虑哪些测试点、往哪些方向测」。**必须结合当前系统裁剪**，禁止整段照搬；每项都给优先级（高/中/低），高风险项优先。

适用于绝大多数 Web / App / API / 企业系统。命中具体业务类型时，再叠加 `business-type-use-cases.md` 对应兜底层。

## 1. 功能 / 业务逻辑
- 主流程：一次完整业务（创建 → 处理 → 结果）是否走通。
- 分支流程：不同条件走不同分支（状态不同、角色不同、数据不同）。
- 关键规则：核心业务规则算对/算错的边界（哪些结果被接受、哪些被拒绝）。
- 状态机：对象在不同状态下是否允许该操作（如草稿→提交→审批→驳回）。

## 2. 输入与数据校验
- 必填：必填项为空如何处理（提示/拦截/默认值）。
- 格式：长度、类型、格式（日期、邮箱、手机号、数值小数位、特殊字符/emoji/XSS 相关字符）。
- 边界：最小值、最大值、刚好临界、越界（等价类 + 边界值）。
- 重复/唯一：重复提交、唯一约束冲突。
- 空值/空集：空列表、空表、无数据时查询/展示。
- 非法：超长、负值、0、极大值、Unicode、注入相关输入。

## 3. 交互与状态变化
- 前后状态都要检查：操作前后对象的可见状态变化（不仅看结果，也看状态字段）。
- 刷新/重进：保存后刷新、重进页面是否仍一致。
- 并发：两个入口同时改同一资源，谁的结果保留（并发写、乐观/悲观锁）。
- 中途失败：操作执行到一半失败，已发生的变化回滚还是保留。
- 幂等：重试是否安全；会不会产生重复订单/重复扣款等副作用。

## 4. 权限与越权
- 认证：未登录访问受保护功能。
- 授权：普通用户访问管理员功能；不同角色看到的数据范围。
- 越权：水平越权（同角色访问他人数据，如换 ID）、垂直越权（低权限执行高权限操作）。
- 数据范围：按角色/组织/租户隔离的查询范围是否正确。

## 5. 依赖与外部系统
- 服务超时/不可用/返回错误：当前系统如何表现（友好提示/降级/重试）。
- 外部接口契约：报文格式、错误码、幂等键。
- 数据一致性：与缓存、队列、下游 DB 的最终一致或强一致。

## 6. 网络与异常恢复
- 网络中断：操作中途断网、弱网、请求超时。
- 重连/恢复：恢复后是否可续传/重试。
- 异常恢复：进程崩溃后数据与状态恢复、事务回滚。

## 7. 性能与容量（按需）
- 响应时间：关键操作在正常与高负载下的延迟。
- 并发/容量：多用户同时操作、大列表、大数据量分页。
- 资源：内存/连接/线程池是否泄漏或耗尽。

## 8. 兼容性与可访问性（按需）
- 浏览器/设备/分辨率：跨浏览器、跨端（Web/App/小程序）、不同分辨率与缩放。
- 无障碍：键盘导航、屏幕阅读器、对比度。

## 9. 安全（按需）
- 鉴权/授权绕过、注入（SQL/XSS/命令）、敏感信息泄露、越权接口、限额/防刷。

## 10. 发布/数据迁移（批次/升级时）
- 数据迁移正确性、旧数据在新规则下的表现、升级回滚。

---

## 输出建议

对每个维度，先问「当前系统这条成立吗？」再决定：
- 成立 → 给出该维度下 1–N 个具体可测点（结合系统场景）。
- 不成立 / 超范围 → 显式标记「不适用」，不要硬造。

把这些测试点汇总到主提示词的「测试方向与测试点」章节，并标优先级。
