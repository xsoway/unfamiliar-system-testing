# 测试理论与技术方法

在「还不懂系统」时按需选用这些经典技术来生成测试方向。按「何时用 / 怎么用 / 适合什么」组织，帮助测试人员决定往哪测。

## 1. 等价类划分（Equivalence Partitioning）
- **何时**：输入可拆成若干「结果相同」的集合时。
- **怎么用**：把所有输入分成有效等价类 + 无效等价类，每类取一个代表值测试。
- **适合**：年龄、金额、状态码、字段取值范围。缺点：默认同类内部等价，可能漏边界。

## 2. 边界值分析（Boundary Value Analysis）
- **何时**：有连续取值范围、要抓 off-by-one 时。
- **怎么用**：测最小值、最大值、刚过边界、边界前后各一。
- **适合**：输入长度、数量上限、日期临界、分页临界。与等价类搭配使用效果最好。

## 3. 决策表（Decision Table）
- **何时**：多个条件组合决定多个结果（业务规则复杂）时。
- **怎么用**：条件列为输入，动作列为输出，穷举条件组合，删去不可能组合。
- **适合**：折扣规则、审批分支、支付方式选择、状态流转前提。能系统化地保证组合覆盖。

## 4. 状态迁移（State Transition）
- **何时**：对象有明显状态机（状态随操作变化）时。
- **怎么用**：列状态图，测每个合法迁移 + 非法迁移（不该发生的跳转）。
- **适合**：订单状态、工单流转、审批流、账号生命周期。前后状态都要断言，不只断言最终结果。

## 5. 探索式测试（Exploratory Testing）
- **何时**：对功能了解有限、想快速发现风险时（正是陌生系统第一步）。
- **怎么用**：同时设计、执行、学习；用 charter（任务卡）限定范围，一次一个目标。
- **适合**：陌生模块快速摸底、找 happy path 之外的意外行为。产出通常是发现列表而非固定用例。

## 6. 基于风险的测试（Risk-Based Testing）
- **何时**：时间有限、必须优先测最重要的地方时。
- **怎么用**：评估每个功能的「失败可能性 × 失败影响」，优先测风险最高的；高风险 ≈ 最大损失处。
- **适合**：紧急工单、回归范围取舍、发布门禁。精神上与最小测试模型的「哪里可能造成最大损失」一致。

## 7. 成对 / 组合测试（Pairwise / Combinatorial）
- **何时**：多个输入维度、全组合爆炸，需压缩时。
- **怎么用**：用成对覆盖保证任意两维组合都被测到，大幅减少用例数。
- **适合**：多条件筛选、配置项组合、批量参数。可用工具生成。

## 8. 用例/场景法（Use Case / Scenario）
- **何时**：业务流程清晰、要覆盖端到端路径时。
- **怎么用**：按用户真实「输入-处理-输出」路径组织用例，覆盖主场景 + 变体场景。
- **适合**：端到端业务流（下单、审批）、异常中断场景。

## 9. 错误猜测（Error Guessing）
- **何时**：对同类系统有经验、能预判常见错误时。
- **怎么用**：凭经验直接列出「很可能出错」的地方测（空值、重复提交、越权、非法格式）。
- **适合**：作为其他技术的补充，快速补漏。本质是把经验放进检查单（见 `test-point-dimensions.md`）。

## 10. 谓词与不变式（Property / Invariant）— 高级
- **何时**：有可自动校验的数学/结构性质时。
- **怎么用**：随机生成输入，断言不变式始终成立（如排序后不丢元素、金额守恒）。
- **适合**：数据处理、算法逻辑、幂等性质（重试结果一致）。

## 11. 蜕变性（Metamorphic）— 高级
- **何时**：难写预期结果、但输入变换导致输出应有确定关系时。
- **怎么用**：测输入变换前后的输出关系（如搜索「价格升序」和「降序」结果互补）。
- **适合**：搜索排序、推荐、AI 输出的相对性质。

## 12. 探索事实的程序性（启发式 HTSM 精神）
- 用启发式模型（功能、风险、质量维度、测试技术、环境、数据、时序、意图）作为大脑里的清单，避免系统性遗漏。
- 它不直接产用例，而是防止「你没想到往哪测」。

---

## 选择建议（陌生系统首轮）

| 你的处境 | 优先技术 |
|---|---|
| 完全不懂、快速摸底 | 探索式（先 happy path，再折腾关键条件） |
| 功能规则复杂、多条件 | 决策表 + 状态迁移 |
| 有取值范围、抓边界 | 等价类 + 边界值 |
| 时间紧、要取舍 | 基于风险（先测最大损失处） |
| 多维度组合爆炸 | 成对/组合 |
| API/幂等/性质类 | 谓词/蜕变性 |

首轮不必全用：先一条 happy path（探索式），再主动改变一个关键条件，每次实验回答一个问题。理解和测试一起推进。
